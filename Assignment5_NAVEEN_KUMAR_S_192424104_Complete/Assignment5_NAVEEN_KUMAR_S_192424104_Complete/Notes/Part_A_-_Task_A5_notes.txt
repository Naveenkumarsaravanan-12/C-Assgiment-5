A5.2 – No Leaks on Errors (2 Marks)

Stack unwinding. When an exception  is thrown, the run-time system searches
outward through the active function calls for a matching catch . Every function it leaves
is exited as if by an early return : the destructors of all fully-constructed automatic
objects in those scopes run, in reverse order of construction. If a constructor
throws, the members and base classes already constructed are destroyed, and memory
obtained by new for the object itself is released.

The output matches. throw 42 leaves f() , destroying its local g ( ~f ); the exception then
leaves the try block, destroying m  ( ~main ) – reverse order of construction – and only
then is the handler entered ( caught 42 ). "not printed" never appears because control
never returns normally from f() : the rest of the try block is skipped. catch (...) is not
used because catch (int x) matches first.
