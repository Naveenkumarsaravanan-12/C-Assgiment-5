 Part A – Task A2: Understand Runtime Binding (5 Marks)

A2.1 – Early and Late Binding (2 Marks)

Binding is the association of a function call with the function body that will execute.

 • Early (compile-time, static) binding: the compiler chooses the function from the
   static type of the expression. For Bill* b , a call to a non-virtual function such as b-
   >name() is bound to Bill::name() at compile time, whatever object b actually points
    to. Calls through objects (not pointers/references) and calls to non-virtual functions
   are bound early; they can be inlined.
 • Late (run-time, dynamic) binding: for a virtual function called through a pointer
   or reference, the choice is made at run time from the dynamic type of the object.
   For Bill* b = new OutPatientBill(…) , the call b->total() executes
    OutPatientBill::total() ; if b later points to an InPatientBill , the same line executes
    InPatientBill::total() .

Each class with virtual functions has one vtable: an array of function addresses, one
slot per virtual function, in a fixed order shared by the whole hierarchy. Every object of
such a class contains a hidden vptr, set by the constructor, that points to its class's
vtable. For Bill the total and type slots point to the run-time "pure virtual called"
handler; derived classes fill those slots with their own functions, while the print slot
still points to Bill::print because no class overrides it.

A call b->total() is compiled as: (1) load the object address from b ; (2) load the vptr
from the object; (3) load the function address from the total slot (a fixed offset) and
call it, passing b as this . The cost is two extra memory loads and an indirect call –
constant time.
