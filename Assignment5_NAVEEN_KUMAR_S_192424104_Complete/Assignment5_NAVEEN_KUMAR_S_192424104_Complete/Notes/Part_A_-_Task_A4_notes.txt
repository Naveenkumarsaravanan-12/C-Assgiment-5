All billing errors derive from BillingError , which derives from std::runtime_error (and
hence std::exception ). A caller can therefore catch a specific error ( ClaimError ), every
billing error ( BillingError ), or anything from the standard library ( std::exception ), and
what() always returns the reason.

 Destructors                  Never       Implicitly noexcept in C++11 and later

Why destructors must not throw. Destructors run during stack unwinding, while
another exception is already propagating. If a destructor throws at that moment there
would be two active exceptions, and C++ calls std::terminate() – the program is killed
and  bills are  lost. Destructors are therefore implicitly  noexcept ; any error during
cleanup must be handled or logged inside the destructor.
