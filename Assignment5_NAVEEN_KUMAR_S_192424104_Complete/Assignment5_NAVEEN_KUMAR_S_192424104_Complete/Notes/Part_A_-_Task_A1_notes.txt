This  report  answers  Assignment  5  (CO5):  reliable  software  with  runtime
polymorphism and exceptions, using the case study of a multi-speciality hospital's
billing and  insurance-claims system.  It  follows the progression required by the
assignment:

  Abstract → Specialise → Bind at Run Time → Detect Errors → Throw → Catch → Recover →
  Measure → Decide

Part A gives the design as UML, vtable and exception-hierarchy diagrams, reasoning
and pseudocode  in the SIMATS standard format (no C++  is used  in place  of
pseudocode; the only programs in Part A are the Predict the Output programs that the
assignment supplies). Part B gives the implementation and the experiments.

A1.3 – Processing All Bills Together (2 Marks)

  ALGORITHM DayTotal(bills, n)
  INPUT  : bills[0..n−1], an array of pointers to Bill objects of any kind
  OUTPUT : sum of the totals of all bills
  BEGIN
    sum ← 0
    FOR i ← 0 TO n − 1 DO
        sum ← sum + bills[i]→Total()        // late-bound call: the object's own Total()
    END FOR
    RETURN sum
  END

The loop never tests which kind of bill it has; adding a new bill kind requires no change
to this algorithm.

Alternative Concept and Complexity Analysis – One Bill Structure with a Type Field

  STRUCTURE Bill: kind ∈ {OP, IP, DC, ER}, patient, a, b, c, d     // union of all
  fields

  ALGORITHM Total(bill)
  BEGIN
    CASE bill.kind OF
       OP : RETURN bill.a + bill.b
       IP : RETURN bill.a × bill.b + bill.c + bill.d
       DC : RETURN bill.a
       ER : RETURN bill.a + bill.b × bill.c
    END CASE
  END
