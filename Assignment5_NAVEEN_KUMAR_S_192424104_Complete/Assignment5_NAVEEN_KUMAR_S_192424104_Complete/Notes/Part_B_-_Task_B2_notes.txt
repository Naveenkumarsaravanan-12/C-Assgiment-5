All three grow linearly (10× bills ≈ 10× time), confirming O(n). Virtual dispatch is
about 25–30 % slower in this micro-benchmark, mainly because each virtual bill is a
separate heap object reached through a pointer (an extra memory access per bill and
poorer cache locality), plus an indirect call that cannot be inlined. The  switch and
variant versions keep all bills contiguous in one array.

B3.3 – Cost of Exceptions (2 Marks)

  Invalid bills   Return code (ms)   Exception (ms)   Extra cost

Exceptions are essentially free when nothing is thrown, but each thrown exception
costs around 1.5–1.7 µs (allocation of the exception object, table search, unwinding) –
about a thousand times a return-code check.

B3.4 – Engineering Trade-Off (2 Marks)

 • Virtual functions cost a few nanoseconds per bill more than a switch. For the
    hospital's 200,000 bills a day, totalling them through virtual calls takes about 3 ms
   in all (≈ 0.6 ms more than with a switch ) – irrelevant – while they allow new bill
   types without editing tested code. Use them when the set of types is open (grows
   over time) and the objects are processed through a common interface.
 • switch / std::variant are fastest and most compact when the set of types is closed
   and stable, data are stored by value in large arrays, and maximum throughput
   matters (e.g. scientific or real-time processing). std::variant additionally gives type
    safety: std::visit fails to compile if a type is not handled.
 • Exceptions should be used for exceptional conditions – invalid input, rejected
   claims that need human review, allocation failure – where the normal path must stay
    fast and errors must not be ignored. Even at an unrealistic 50 % invalid rate,
   200,000 bills would spend only ≈ 0.17 s a day in exception handling.
 • Return codes / std::optional are better when failure is a normal, frequent outcome
   inside a tight loop (for example, filtering millions of candidate records).
